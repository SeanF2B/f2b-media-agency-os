# Marketing Studio

Marketing Studio adds Funnels, Forms, Surveys and Calculators inside **Sites**, plus an **Automations** workspace in the existing CRM.

## Current capabilities

- Owner/admin-only project library, scoped to the existing workspace owner and optional client.
- The project-list API uses bounded limit/offset pagination with stable `updated_at, id` ordering and owner-scoped queries; the UI loads 100 projects at a time and offers Load more.
- Owner-scoped folders for each builder type; projects can be filed, filtered, and moved between folders from the library/editor.
- Versioned draft records in D1, saved project history capped at the 25 newest versions, rollback into a draft, debounced autosave after an initial save, up to 50 undo/redo snapshots in the editor, and new draft copies of existing projects or fields. Restoring or editing a draft does not replace the last published page.
- AI-generated and AI-edited editable drafts, with screenshot input. The AI route requires the existing server-side OpenAI connection, is limited to 30 requests per owner per UTC day, and keeps prices at zero until the owner supplies them.
- Import of a saved client website or campaign page over HTTPS. The page must match a domain already stored on that client; redirects to another host, local/IP URLs, non-HTML responses and bodies above 1 MB are rejected. Imported page text is untrusted input.
- Funnel pages with ordered steps and editable, reorderable hero, text, image, call-to-action, FAQ, testimonial, pricing, responsive two-to-four-column blocks, and one-level nested stack/two-column/three-column containers with editable child blocks. Column cards support headings, copy and optional HTTPS calls to action. The CRM editor and published HTML both stack layouts on narrow screens. Global design settings save brand, background and text colours, an allowlisted font choice and a bounded content width; individual page sections can also set safe background/text colour, spacing, alignment, and device-specific overrides. The draft preview and published HTML use the same settings. Funnel drafts also save SEO title, description, canonical URL, Open Graph image and no-index settings; published pages render these as crawlable metadata and semantic HTML.
- Funnel sections and nested container blocks can be conditionally shown from up to eight answer fields with AND/OR logic. The editor preview includes answer controls for referenced fields; published pages update visibility immediately as answers change. Save and AI-generation routes validate section references against the project fields.
- Owner-scoped reusable funnel sections can be saved from any draft, inserted into another funnel in the same workspace, and removed from the library without changing existing funnels.
- Owner-authorized project analytics show daily page loads, submissions and submissions per load for the last 30 UTC days. Only aggregate counts and allowlisted UTM tags attached to a submitted lead are stored; repeat visits count separately, crawler requests may be included, and visitor IP addresses and identities are not collected. Direct and embedded forms preserve `utm_source`, `utm_medium`, `utm_campaign`, `utm_content` and `utm_term` through funnel steps and show them beside the CRM submission. No visitor cookie or click ID is stored.
- Funnel images can be uploaded as PNG, JPEG or WebP (maximum 1 MB) to the dedicated private R2 bucket. The management route scopes reads and writes to the signed-in workspace; published pages expose only image objects referenced by that page's published version through the public page route. R2 public bucket access remains disabled.
- Forms, surveys and calculators with editable fields, required-field checks, dropdowns, address inputs, private file uploads (PDF, PNG, JPEG or WebP; 5 MB total per submission), content headings/descriptions/dividers, survey progress markers, drag-reorder, survey question drag-between-step targets, and field-visibility rules for equality, inequality, numeric comparisons, contains and empty checks. Fields can explicitly map to standard GoHighLevel contact fields or be excluded from sync; unmapped fields retain conservative label-based detection. Submission files are stored in the private R2 bucket and downloadable only to owner/admins. Address inputs use browser street-address autofill and map into GoHighLevel's address field. Consent answers and uploaded files are never included in contact sync. Content-only fields cannot be marked required or submitted as answers. Each field supports up to eight conditions combined with AND or OR; the builder rejects missing references and circular dependencies.
- Surveys with up to ten configured steps, forward-only answer branches, and conditional questions that remove empty steps from the visitor path. Both the browser flow and server-side required-field validation use the same visible path. Calculators show a live estimate and the server recalculates the saved total when a visitor submits. Quote snapshots retain the published calculator version, a digest of its pricing rules, currency, line items, subtotal, fees, minimum-charge adjustment, discount, taxable subtotal, tax, final estimate and submission timestamp. A calculated field can combine up to eight earlier numeric/calculated inputs for multiply or add, or exactly two for subtract or divide, then price that result with the same flat or tiered rates; client-submitted calculated values are ignored.
- Calculator line-item prices can be gated by a saved answer condition, including equals, not-equals, numeric comparisons, contains and empty checks. The published estimate and submission-side quote use the same condition, and invalid question references are rejected.
- Published-page rendering and submission APIs at `/f/{slug}` (with `/api/marketing-public?slug=...` retained for compatibility), responsive iframe snippets with a strict origin/source/slug-checked height handshake, allowed-domain frame policy, bounded submissions, honeypot spam check, atomic per-published-page limit of 60 submissions per minute (without storing visitor IP addresses), and owner-only submission viewer. A local Worker end-to-end check returned HTTP 200 for public rendering and submission, verified SEO and each block type in the HTML, and confirmed the submitted email was saved to the isolated D1 test database.
- Owner/admins can delete an individual submission from its viewer; its private R2 attachments and workflow run records linked to that submission are removed too. The UI confirms before deletion, and the stored daily submission count is decremented. A GoHighLevel contact already created by sync is not erased by this action. Workspace owners can opt into automatic 30-, 90-, 180- or 365-day retention from any non-automation builder; it is off by default. The five-minute scheduled cleanup processes 50 submissions per tick, pages past storage failures, and preserves a submission if its private attachment cannot be deleted.
- Explicit client ownership checks on management routes. Public submissions cannot select a tenant or asset ID; the server resolves the published slug and stores the correct owner and asset.
- Background GoHighLevel contact, tag, DND, appointment, opportunity, birthday, date-field and inbound-reply triggers for automations, scoped to the exact linked client location. The webhook accepts only HighLevel's Ed25519-signed raw requests, caps request bodies at 64 KB, normalizes allowlisted fields, stores only fields referenced by workflow steps, and de-duplicates deliveries. Tag added/removed triggers compare successive tag snapshots; the first tag event establishes the baseline. ContactUpdate, tag-change, DND, appointment and opportunity events cannot update the source contact, preventing loops or unsupported writes. Customer messaging from a bare contact webhook remains disabled because the event does not establish marketing consent.

## API map

All management endpoints below use the existing CRM session and then verify the user is the workspace owner or an agency admin. Client, project, submission, folder and image queries are scoped to the workspace owner on the server. Public submission requests resolve the project by its published slug; callers cannot choose an owner or asset ID. Production Cloudflare Access currently protects the whole app hostname, including visitor routes, until a path-specific exception is approved.

| Route | Purpose |
| --- | --- |
| `GET/POST/DELETE /api/marketing-studio?kind=funnel\|form\|survey\|calculator\|automation` | List and save/delete projects; save endpoints also handle folders, publication, activation/pause, versions, submission retention, reusable sections and message-status refresh. List requests support `limit`/`offset`. |
| `GET /api/marketing-studio?submissions=1&assetId=…` | Read the signed-in owner's submissions for a project. |
| `GET /api/marketing-studio?analytics=1&assetId=…&range=last_7d\|last_30d\|last_90d\|custom` | Read project page-load and submission aggregates; custom ranges require `from` and `to` and are bounded to 366 days. |
| `GET /api/marketing-studio?publishedSources=1` | Return the owner's published tools and allowlisted field schemas for automation setup. |
| `GET /api/marketing-studio?ghlDateFields=1&clientId=…` | Read custom date/status fields from that client's linked GoHighLevel location. |
| `POST /api/marketing-studio/generate` | Generate or edit a structured draft from text, an optional screenshot, an existing project, or imported page text. Output is schema constrained and remains a draft for review. |
| `POST /api/marketing-studio/import` | Read a public HTTPS page on the selected client's saved website/campaign host and return bounded page text for AI drafting. Cross-host redirects and local/private-style URL forms are rejected. |
| `POST/GET /api/marketing-studio/assets` | Upload/read owner-scoped PNG, JPEG and WebP builder images in private R2 storage. |
| `GET /api/marketing-studio/submission-files?submissionId=…&fileId=…` | Download a private attachment only after owner/admin and submission ownership checks. |
| `GET/POST /api/marketing-studio/domains` | List, add, TXT-verify and remove owner-scoped mappings for published pages. TXT verification proves ownership only; it does not provision Cloudflare for SaaS or DNS routing. |
| `GET/POST /api/marketing-public?slug=…` and `GET /f/{slug}` | Render published SEO HTML and accept validated public form/survey/calculator submissions. The public handler enforces required/visible fields, same-origin or configured embed origins, rate limits, server-calculated quotes and owner resolution. |
| `POST /api/gohighlevel/webhook` | Receive signed GoHighLevel events, verify Ed25519 before accepting, normalize allowlisted fields and queue matching automation triggers. The Marketplace app must subscribe the desired event types. |

These routes follow the CRM's existing `/api` convention rather than introducing a second `/api/v1` surface. Responses use JSON errors and HTTP status codes; public forms return an HTML confirmation/validation page or a redirect for successful non-embedded submissions.
